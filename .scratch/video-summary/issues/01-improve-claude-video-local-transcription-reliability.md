Title: 提高 Claude Video 本地中文转写与多视频理解的可靠性
Target: `/Users/yxy/study-code/claude-video`

## 背景

在整理 4 条中文本地视频时，需要先通过 Claude Video 取得完整转录，再结合关键画面核对作者观点、专有名词和博主案例。

本次素材总时长约 25 分钟：

- 《拿回叙事权之后，自媒体开始赚钱了》：约 3 分 55 秒；
- 《一条视频讲清楚什么是意识形态定位》：约 10 分 20 秒；
- 《怎么看自己能不能吃上自媒体这碗饭》：约 4 分 8 秒；
- 《搞明白2个问题，自媒体直接开挂》：约 6 分 53 秒。

Claude Video 已经能够完成本地音频提取、`whisper.cpp` 转录、缓存和指定时间点截图，但整个过程中暴露出几项会直接影响结果可信度的问题。最终总结能够完成，主要依赖人工强制指定中文、重新运行转录，并逐帧核对视频内嵌字幕。

相关整理结果：[李守洲自媒体方法论：四条视频结构化总结](../李守洲自媒体方法论-四条视频结构化总结.md)。

## 实际遇到的困难

### 1. 首次环境检查没有识别已经配置好的本地转写后端

本机的 `~/.config/watch/.env` 已经配置：

- `WATCH_LOCAL_WHISPER_BIN`
- `WATCH_LOCAL_WHISPER_MODEL`
- `WATCH_LOCAL_WHISPER_CHUNK_SECONDS`

对应的可执行文件和模型均存在，实际使用 `--whisper local` 也能成功转录。

但是运行：

```bash
python3 skills/watch/scripts/setup.py --json
```

得到的结果仍然是：

```json
{
  "status": "needs_key",
  "can_proceed": false,
  "first_run": true,
  "whisper_backend": null,
  "has_api_key": false
}
```

这会误导调用方认为必须安装新工具或配置 Groq/OpenAI 密钥，尽管本地转写能力已经可用。

### 2. 中文语音被自动识别成英文，产生大段英文幻听

使用本地 `ggml-base.bin` 模型、不显式指定语言时，第一轮转录把普通话误判成英文。

典型结果包括：

```text
[00:00] One of the things you can do is to do the highest part of the media and the media.
[00:03] It's also a thing that can be done by our culture.
```

后半段还出现同一句英文反复重复的现象。报告仍把这份结果作为正常转录输出，没有提示语言识别异常、重复率过高或结果可能不可用。

最终只能通过额外传入以下参数重新运行：

```bash
WATCH_LOCAL_WHISPER_ARGS='-l zh -ng'
```

指定中文后，内容才恢复到基本可理解的状态。

### 3. 强制中文后仍有大量关键同音词和专有名词错误

自动语音识别 (Automatic Speech Recognition, ASR) 能恢复主要句意，但关键概念和名字仍频繁出错。例如：

| 实际内容 | 转录结果示例 |
| --- | --- |
| 流量 | 牛娘 |
| 爆款 | 抱款、爆锅 |
| 叙事体系 | 虚实体系 |
| 实然问题、应然问题 | 实谅新问题、英兰问题 |
| 原子化 | 原始化 |
| 集体欢腾 | 集体欢弹 |
| 涂尔干 | 土耳杆 |
| 齐美尔 | 其美而 |
| 这很斯远 | 正式远 |
| 方比比先生 | 方便比 |
| dontbesilent | 东西山安德 |
| 经纬老师、陈晶老师、参哥 | 金伟老师、陈静老师、深哥 |

这些错误不是普通错别字，而是会改变观点含义或导致案例归属错误。仅依靠转录文本，无法可靠生成结构化总结。

### 4. 视频内嵌字幕没有参与转录纠错

本次 4 条视频都带有清晰的画面字幕。人工查看画面后，可以直接确认“叙事体系”“自我开源”“承担风险”以及多个账号名称。

当前流程把转录和画面作为两份并列证据输出，但没有自动使用画面文字识别 (Optical Character Recognition, OCR) 结果去校正 ASR。结果是：机器已经拿到了包含正确文字的画面，却仍把错误转录交给调用方人工修正。

### 5. 指定时间点截图容易错过短暂出现的姓名或字幕

使用 `--timestamps` 在转录提到案例的时间点抓图时，截图可能早于字幕或账号卡片出现。例如在 `07:36` 抓图，只看到作者开始引入案例；真正的账号名要到 `07:41` 左右才出现。

为了确认名字，最终需要围绕目标时间点反复抽取相邻秒数，部分位置还要使用小数秒：

```text
07:39 → 只出现口头引入
07:41 → 出现“这很斯远”账号卡片
03:49.8 → 出现“经纬老师”
03:50.3 → 出现“陈晶老师”
03:51 → 出现“参哥”
```

单帧精确时间点并不足以稳定覆盖这类短暂视觉证据。

### 6. 本地 GPU 失败后退回 CPU，批量处理时成本不透明

每条视频首次转录都出现：

```text
[watch] local Whisper GPU failed; retrying CPU-only with -ng
```

自动回退让任务最终能够完成，这是正确行为；但调用前无法知道 GPU 是否可用、预计使用哪个设备，以及批量处理多条视频时大概需要多久。

如果调用方并行启动多个视频，多个 CPU 转录进程还会同时争抢资源。最终为了稳定处理，只能取消并行转录，改为逐条运行。

### 7. 长转录主要写到标准输出，容易在调用链中被截断

10 分钟视频会产生数百个分段。完整报告直接输出到标准输出，经过上层工具后可能因长度限制被截断。

Claude Video 内部虽然保留了缓存和 JSON 产物，但最终报告没有提供一个足够明确、稳定、适合后续程序读取的“规范转录文件”入口。批量处理时，调用方容易只拿到不完整文本。

## 复现步骤

### 复现环境识别问题

1. 在 `~/.config/watch/.env` 配置有效的本地 `whisper.cpp` 路径和模型。
2. 不配置 Groq/OpenAI 密钥。
3. 运行：

```bash
python3 skills/watch/scripts/setup.py --json
```

4. 观察 `can_proceed: false`、`whisper_backend: null`。
5. 再对任一本地视频运行 `watch.py <video> --whisper local`，确认本地转写实际可用。

### 复现中文误判问题

1. 准备一条只有普通话语音、没有独立字幕轨的 MP4 文件。
2. 使用 `ggml-base.bin`，不传 `-l zh`。
3. 运行：

```bash
python3 skills/watch/scripts/watch.py "<video.mp4>" \
  --detail transcript \
  --whisper local
```

4. 观察转录是否被识别为英文，或出现高比例重复文本。
5. 加入 `WATCH_LOCAL_WHISPER_ARGS='-l zh -ng'` 后重跑，比较两次结果。

## 期望行为

1. 环境检查应把有效的本地 Whisper 配置视为可用后端，不应要求云端密钥。
2. 中文视频应能通过显式配置或可靠检测选择中文，而不是静默输出英文幻听。
3. 当输出出现语言不匹配、异常重复或低可信度时，应明确警告，不能把结果包装成正常报告。
4. 对带清晰内嵌字幕的视频，应能选择使用 OCR 辅助校正关键词和专有名词。
5. 时间点截图应支持围绕目标时间抓取一个短窗口，而不是只取一帧。
6. 批量运行前应能看见实际计算设备和回退策略。
7. 长转录应有稳定的结构化文件输出，标准输出只负责摘要和文件位置。

## 建议方案

### A. 修正本地后端的环境检查

- 让 `setup.py --json` 调用与 `watch.py` 相同的 `local_whisper_status()` 判断。
- 当本地二进制和模型有效时返回：

```json
{
  "can_proceed": true,
  "whisper_backend": "local",
  "has_api_key": false
}
```

- 分别报告本地配置缺失、本地路径失效和云端密钥缺失，不要把它们合并成 `needs_key`。

### B. 增加一等语言配置和质量检查

- 为 `watch.py` 增加 `--language zh`，并提供对应的持久配置，例如 `WATCH_TRANSCRIPT_LANGUAGE=zh`。
- 报告实际使用的语言、模型和计算设备。
- 对以下情况发出高优先级警告：
  - 检测语言与用户指定语言冲突；
  - 单句或短语重复率异常；
  - 大部分结果与指定语言字符分布不一致；
  - Whisper 返回可用的低置信度信号。
- 在语言检测明显异常时，允许自动按配置语言重试一次。

### C. 增加字幕画面辅助校正

- 提供可选的 `--verify-transcript-with-frames` 或同等能力。
- 对字幕区域进行 OCR，并按时间对齐 ASR 分段。
- OCR 与 ASR 冲突时，不应无提示地覆盖；应保留原始值、建议修正值和证据时间点。
- 优先用于标题、账号名、专有名词和反复出现的核心概念。

### D. 改进时间点取帧

- 为 `--timestamps` 增加窗口模式，例如每个时间点自动获取 `-1s`、`0s`、`+1s` 三帧。
- 对连续字幕或账号卡片，可允许在小窗口内选择文字最完整的一帧。
- 报告最终选中帧与用户给定时间点之间的偏移。

### E. 提供稳定的结构化输出

- 增加 `--json-output <path>` 或默认生成 `report.json` 与 `transcript.json`。
- 最终标准输出明确列出这些文件的绝对路径。
- 结构化结果至少包含：
  - 视频身份、时长和分辨率；
  - 转写后端、模型、语言和计算设备；
  - 完整分段及时间点；
  - 质量警告；
  - 缓存命中情况；
  - 帧路径和选择原因；
  - OCR 建议修正及其证据。

## Acceptance criteria

- [ ] 已配置且有效的本地 Whisper 后端在 `setup.py --json` 中返回 `can_proceed: true` 和 `whisper_backend: "local"`，无需云端密钥。
- [ ] `watch.py` 支持显式 `--language zh`，且该设置会进入缓存键，避免复用错误语言的旧缓存。
- [ ] 使用普通话测试素材且指定中文时，不再输出整段英文幻听。
- [ ] 对语言不匹配和高重复率转录给出机器可读的质量警告。
- [ ] GPU 不可用时，报告实际回退到 CPU；批量调用方可以在正式转录前查询设备状态。
- [ ] `--timestamps` 支持可配置的相邻帧窗口，并能覆盖短暂出现的账号卡片或字幕。
- [ ] 提供稳定的完整结构化转录文件；即使标准输出被截断，调用方仍能从报告路径取得全部分段。
- [ ] 至少用一条带清晰中文字幕的普通话视频验证 OCR 辅助校正，证明它能纠正核心概念或账号名，同时保留原始 ASR 证据。
- [ ] 自动化测试覆盖：本地后端可用、无云端密钥、中文显式语言、英文误判告警、GPU 回退、缓存隔离、长输出和时间窗口取帧。

## Out of scope

- 要求轻量模型达到人工逐字稿级别的零错误率。
- 自动通过网络搜索猜测博主真实身份。
- 默认把本地视频或音频上传到云端。
- 在本 Issue 中修改 `25-info-workflow` 的视频适配器。
